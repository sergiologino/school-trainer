# Архитектурные решения

Формат записи: дата (если известна), решение, причины, статус (**Active** / **Superseded**).

---

## Active — монорепозиторий и один основной backend

**Решение:** развивать проект как **монорепозиторий** с одним **frontend** и **одним backend API** на старте.

**Причины:** проще синхронизировать версии контрактов, деплой и рефакторинг при объединении трёх PWA; при росте нагрузки или команд части можно вынести в отдельные сервисы с тем же внешним API.

---

## Active — канонический контент в БД через API

**Решение:** темы программы по математике (структура уроков) и статические массивы заданий/слов (**русский**, **английский**) хранятся в SQLite и отдаются фронту через REST; генерация многих числовых вариантов (таблица умножения, дроби, десятичные дроби, новые блоки процентов/площади/среднего) остаётся в клиентском коде.

**Причины:** ослабляет привязку программы к релизу SPA, сохраняет быстрые и богатые тренажёры математики без серверного движка вычислений.

---

## Active — offline-first content packages для web и mobile

**Решение:** основа масштабирования контента — `content_item` и `content_package` в SQLite. `content_item` хранит опубликованные элементы по предмету, классу, типу и версии; `content_package` хранит версионированные JSON-пакеты с checksum для синхронизации. Web скачивает пакеты через `/api/content/manifest` и `/api/content/packages/:key` и кеширует локально; будущий mobile-клиент использует тот же API, но хранит пакеты в локальной SQLite.

**Причины:** единый backend-контракт для web и mobile, офлайн-доступность через пакетную синхронизацию, возможность добавлять предметы, классы, ВПР/ОГЭ/ЕГЭ и медиа без хардкода в клиенте. Legacy `curriculum_topic`/`content_bundle` оставлены для совместимости текущих экранов.

---

## Active — сборка контент-артефактов перед сидированием

**Решение:** `backend/scripts/extract-client-bundles.mjs` вытягивает данные из `frontend/src/subjects/` (в том числе расширения сидируемого набора в самом скрипте), пишет JSON в `backend/content/_generated/`, после чего `seed.ts` загружает БД.

**Причины:** не писать сотни INSERT вручную; сохранять одну редакцию текстов задач между клиентским fallback и базой.

---

## Active — память проекта только в docs/ai/

**Решение:** единственный источник истины для контекста проекта — файлы под `docs/ai/` по согласованному набору; история чата не является памятью.

**Причины:** воспроизводимость и передача знаний между сессиями и разработчиками.
