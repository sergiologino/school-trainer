# Конвенции проекта

## Память (docs/ai/)

- Перед задачами читать все актуальные файлы в `docs/ai/`.
- В память не писать: логи, stack trace, промежуточные гипотезы и черновые рассуждения — только итоговые факты.
- При ошибочном решении помечать **Superseded** в `DECISIONS.md` и привести код в соответствие.

## Изменения в коде

- Минимально инвазивно: не ломать рабочий функционал без явного запроса; без массовых рефакторингов без необходимости.
- Любые значимые изменения в коде сопровождать обновлением `CURRENT_STATE.md`.

## Тестирование и сборка

- На новые фичи — **автотесты**.
- Тесты должны **запускаться при каждой сборке** CI/скриптов сборки; при падении — исправить причину и повторить сборку.

## Код и стиль

- Следовать существующим шаблонам в репозитории после появления кода (имена, типы, структура пакетов).
- Коммиты и описания задач — ясными полными предложениями без лишнего шума.

## Доменная документация

При росте проекта добавлять файлы в `docs/ai/domains/` по предметным областям или сервисам (например `content.md`, `backend-api.md`).
